# 安全凭证吊销指引（Legacy Credential Revoke）

## 背景

规划阶段的旧客户端曾计划在 `hospital-ai-miniapp/config/api.js` 中明文内置第三方 AI / 语音服务
的凭证。该文件**未进入本仓库的任何提交**（`git log --all -- '*api.js'` 零命中，`git ls-tree`
在历史提交中也不存在该路径），因此不存在「已提交后被移除」或「被存根化」的历史。

真正发生的问题是：本仓库已被推送到**公开的 GitHub 远端**（`origin` 为 GitHub 地址，远端分支
含全部提交）。文档中曾写入可定位账号的凭证标识（完整的方舟推理接入点 ID 与若干密钥前缀）
以及对应控制台路径。按安全基线，凭证标识一旦进入公开可见面即应视为**已泄露
（compromised）**，必须吊销重建。

**移出仓库不等于吊销**：密钥本身仍然有效，必须由用户在对应控制台手动吊销。另注意，
**改写 Git 历史或强推不会让已存在的 fork、镜像与第三方缓存失效**，故吊销是唯一能真正止损的动作。

## 禁止事项

- 不得在本仓库任何文件（含文档、证据）中写入完整凭证值。
- 不得从本地 Git 历史中"恢复"旧凭证。
- 在完成吊销、把仓库改为 Private 并清理已推送历史之前，**不得再将本仓库 push 到任何远端**（当前已推送状态见上文「背景」）。
